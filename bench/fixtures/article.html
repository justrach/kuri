The token economics of browser agents

An accessibility snapshot is the interface an agent uses to see a page. Its size, in tokens, is paid on every single step of a trajectory. This post walks through where those tokens go and how a diff-based loop changes the arithmetic.

Where the tokens go

A naive serialization of the DOM is enormous. The accessibility tree is smaller, but a full a11y snapshot of a content-heavy page still runs into the thousands of tokens. Most of that is stable structure that does not change between steps.

Consider a twenty-step task. If each step re-sends the full snapshot, the agent pays for the navigation chrome, the footer, and the sidebar twenty times over. Only a handful of nodes actually change after a click.

The diff loop

A diff loop sends the full snapshot once, then sends only added, removed, and changed nodes after each action. The steady-state cost per step drops from the size of the page to the size of the change.

Compiled replay

Once a trajectory succeeds, its actions can be recorded and replayed deterministically. A replay run pays zero model tokens unless it diverges, at which point a recovery agent inspects the diff and repairs the script.

Conclusion

Format matters, but loop economics matter more. The cheapest snapshot is the one you do not have to send twice.
